# ညောင်တုန်း ပါဠိတက္ကသိုလ် ကျောင်းသားဟောင်းများ ဆက်သွယ်ရေးနှင့် မှတ်တမ်းစနစ် - Architecture & Policy မှတ်စုများ

## အဓိက ရည်မှန်းချက် ၅ ပိုင်း (Alumni Directory & Contact Management System)
1. ကျောင်းသားဟောင်းများ၏ ကိုယ်ရေးအချက်အလက် စုဆောင်းခြင်း
2. ကိုယ့်အချက်အလက် ပါဝင်ပြီး/မပါဝင်သေးကြောင်း စစ်ဆေးခြင်း
3. မှားယွင်းနေသော အချက်အလက်များကို ပြင်ဆင်ခြင်း
4. ကိုယ်ရေးအချက်အလက်များကို မသမာသူများ၏ ရယူမှုမှ ကာကွယ်ခြင်း (Privacy-first Design)
5. စုဆောင်းထားသော အချက်အလက်များကို ပြည်တွင်း/ပြည်ပ ခွဲခြားပြီး ပုံနှိပ်စာအုပ်ထုတ်ဝေခြင်း

**အခြေခံမူ ၄ ချက်:** Accuracy (မှန်ကန်မှု), Privacy (လုံခြုံမှု), Verification (အတည်ပြုနိုင်မှု), Sustainability (ရေရှည်ထိန်းသိမ်းနိုင်မှု)

---

## ၁။ နိုင်ငံတကာ Alumni Directory နမူနာများမှ သင်ခန်းစာ ၃ ခု
*(Princeton TigerNet, Columbia, Stanford, UMich, Oxford Alumni)*
* ကိုယ့်အချက်အလက်ကို ကိုယ်တိုင်ပြန်စစ်ပြီး ပြင်ဆင်နိုင်ရမည်။
* ဘယ်သူက ဘယ်အချက်အလက်ကို မြင်နိုင်မလဲဆိုတာ ထိန်းချုပ်နိုင်ရမည်။
* ကျောင်းသားဟောင်းတစ်ဦးချင်းစီ၏ ခွင့်ပြုချက်မရှိဘဲ အချက်အလက်များကို အစုလိုက်အပြုံလိုက် ရယူနိုင်ခြင်း (Bulk Scraping / Download) ကို ကာကွယ်ရမည်။

## ၂။ အချက်အလက် ဖွဲ့စည်းပုံ (Data Schema Categories)

### A. ကိုယ်ရေးအချက်အလက်
* ဘွဲ့/အမည် (မဖြစ်မနေ)
* အမည်ကွဲ/အမည်ဟောင်း (ရှာဖွေရလွယ်ရန်)
* ဓာတ်ပုံ (ဆန္ဒရှိမှ)
* သာသနာ့ဘွဲ့/လူအမည်
* ကျောင်းဝင်ခဲ့သည့်နှစ် (အကြံပြု)
* ကျောင်းထွက်/ပြီးဆုံးခဲ့သည့်နှစ် (အကြံပြု)
* သင်ယူခဲ့သော အတန်း/ဘွဲ့ (အကြံပြု)

### B. ကျောင်းနောက်ခံအချက်အလက်
* မူလကျောင်း: ပါဠိတက္ကသိုလ် ညောင်တုန်းကျောင်း
* ကျောင်းတိုက်နေခဲ့ဖူးသော ကျောင်းဆောင်
* ကျောင်းဆောင်အခန်း/အဆောင်အမည် (ရှိလျှင်)
* အတူနေခဲ့ဖူးသော သူငယ်ချင်း (ရွေးချယ်နိုင်)
* ကျောင်းသားဟောင်းအဖွဲ့/အသုတ် (ရှိလျှင်)

### C. လက်ရှိနေထိုင်ရာ (ပြည်တွင်း / ပြည်ပ ခွဲခြား + မွေးရပ်ဇာတိ သီးခြားခွဲရန်)
* **ပြည်တွင်း:** တိုင်းဒေသကြီး/ပြည်နယ် → ခရိုင် → မြို့နယ် → မြို့/ရွာ → ရပ်ကွက်
* **ပြည်ပ:** နိုင်ငံ → ပြည်နယ်/တိုင်း (ရှိလျှင်) → မြို့ → လိပ်စာအသေးစိတ် (Optional)

### D. ဆက်သွယ်ရန်အချက်အလက်
* ဖုန်းနံပါတ် (အဓိက), ဒုတိယဖုန်းနံပါတ် (Optional)
* Email (Optional), Telegram Username (Optional), WhatsApp (Optional)
* ဆက်သွယ်နိုင်သည့် နည်းလမ်း

### E. Admin ထံသိစေလိုသောအချက်အလက် (Private - Admin Only)
* မှားယွင်းနေသော အချက်အလက် ပြင်ဆင်ရန်
* အခြားကျောင်းသားဟောင်းတစ်ဦးအတွက် အချက်အလက်ပေးရန်
* စာအုပ်ထုတ်ဝေရာတွင် ထည့်သွင်းစေလိုသော အချက် / အခြားမှတ်ချက်

## ၃။ ကိုယ့်အချက်အလက် ပါပြီး/မပါပြီး စစ်ဆေးခြင်း Workflow
1. **အမည်နှင့် ကျောင်းဝင်ခဲ့သည့်နှစ် ရှာဖွေခြင်း** (ဥပမာ- အရှင်ဉာဏိက၊ ၂၀၁၀)
2. **ရှိပြီးသား မှတ်တမ်းများကို ပြသခြင်း** (ဖုန်းနံပါတ်နှင့် လိပ်စာအပြည့်အစုံ မပြသရန်)
3. **ကိုယ်ပိုင်မှတ်တမ်းဖြစ်ကြောင်း အတည်ပြုခြင်း** (Admin ထံ တိုက်ရိုက်အတည်ပြုခြင်း / ကျောင်းသားဟောင်းတစ်ဦး၏ အတည်ပြုချက် / ကျောင်းတက်နှစ်-ကျောင်းဆောင် တိုက်ဆိုင်စစ်ဆေးခြင်း / အထောက်အထား သီးသန့်ပေးပို့ခြင်း)
4. **အတည်ပြုပြီးမှ ကိုယ်ပိုင် Profile ပြင်ဆင်ခြင်း**

**Record Statuses:** `Pending`, `Verified`, `Needs Correction`, `Under Review`, `Hidden`, `Rejected`

---

## ၄။ လုံခြုံရေးနှင့် Access Level ၃ မျိုး

* **Level 1 — Public (အများပြည်သူ):** စီမံကိန်းအကြောင်း၊ စုစုပေါင်းအရေအတွက်၊ ပြည်တွင်း/ပြည်ပ အရေအတွက်၊ မှတ်ပုံတင်လမ်းညွှန် (ကိုယ်ရေးအချက်အလက်၊ ဖုန်း၊ လိပ်စာ မမြင်ရ)
* **Level 2 — Verified Member (အတည်ပြုပြီး ကျောင်းသားဟောင်း):** အခြားသူများကို ရှာဖွေနိုင်၊ အမည်/ဘွဲ့/ကျောင်းဆောင်/မြို့ ကြည့်နိုင်၊ Contact Request တောင်းဆိုနိုင်၊ မိမိ Profile ပြင်ဆင်နိုင် (ဖုန်းနံပါတ်ကို ပိုင်ရှင်ခွင့်ပြုမှ မြင်ရ)
* **Level 3 — Admin (Restricted):** စီမံခန့်ခွဲခြင်း၊ Approve/Edit/Delete၊ စာအုပ်အတွက် Data Export၊ Audit Logs

**မဖြစ်မနေ Security Features:**
OTP Verification, Admin Approval, Rate Limiting, CAPTCHA, Login Protection, Role-based Access, Audit Log, Encrypted Backup, HTTPS

**Contact Request Flow:** ဖုန်းနံပါတ် တိုက်ရိုက်မပြဘဲ "ဆက်သွယ်ရန် တောင်းဆိုမည်" ခလုတ်မှတစ်ဆင့် ပိုင်ရှင်က လက်ခံမှ ဖုန်း/Telegram မျှဝေခြင်း။

## ၅။ ပုံနှိပ်စာအုပ်ထုတ်ဝေရေး (Print Edition)
* **ဖွဲ့စည်းပုံ:** မိတ်ဆက် → ပြည်တွင်း (တိုင်းဒေသကြီး/ပြည်နယ်အလိုက်) → ပြည်ပ (နိုင်ငံအလိုက်) → အမည်အက္ခရာစဉ် Index → မှတ်တမ်းပြင်ဆင်ရန် လမ်းညွှန်
* **Granular Print Consent:** အမည်နှင့်ဘွဲ့ / မြို့နှင့်နိုင်ငံ / ဖုန်းနံပါတ် / ဓာတ်ပုံ တစ်ခုချင်းစီအတွက် စာအုပ်ထဲထည့်သွင်းရန် သဘောတူညီချက် သီးခြားယူရန်။
* **Edition Versioning:** ထုတ်ဝေပြီးနောက် ပြင်ဆင်မှုများကို နောက် Edition တွင် ခြေရာခံနိုင်ရန်။

## ၈။ အဆင့်လိုက် အကောင်အထည်ဖော်မှု (Phases)
* **Phase 1 — Data Collection:** Form, ပြည်တွင်း/ပြည်ပ ခွဲခြားမှု, Admin Approval, Duplicate Check
* **Phase 2 — Alumni Directory:** Login/Register, ရှိ/မရှိ စစ်ဆေးခြင်း, Profile Update, Search, Contact Request, Privacy Settings
* **Phase 3 — Security & Administration:** Role-based Access, OTP, Audit Log, Rate Limiting, Backup & Restore, Data Access Monitoring
* **Phase 4 — Book Publishing:** Data Export, အက္ခရာစဉ် စီစဉ်ခြင်း, စာမျက်နှာနံပါတ်, Print-ready PDF
* **Phase 5 — Community:** Announcement, Reunion, Alumni News, Regional Alumni Groups

## ၉။ မစတင်မီ ဆုံးဖြတ်ရမည့် အဓိကမေးခွန်း ၅ ချက်
1. **ဘယ်သူတွေ စာရင်းသွင်းခွင့်ရှိသင့်သလဲ** (သင်ကြားခဲ့ဖူးသူအားလုံး / ဘွဲ့ရပြီးသူများသာ / နှစ်မျိုးစလုံး အမျိုးအစားခွဲ)
2. **အချက်အလက်ကို ဘယ်သူတွေ မြင်ခွင့်ရှိသင့်သလဲ** (Verified များသာ / အများပြည်သူ / အမည်-ဘွဲ့ Public နှင့် ဖုန်း-လိပ်စာ Member Only)
3. **ပုံနှိပ်စာအုပ်ကို ဘယ်သူတွေအတွက် ရည်ရွယ်ထားသလဲ** (ကျောင်းသားဟောင်းများသာ / အများပြည်သူ / အတွင်းသုံး-အများသုံး သီးခြား)
4. **အချက်အလက် အတည်ပြုခြင်းကို ဘယ်လိုလုပ်ချင်သလဲ** (Admin ကိုယ်တိုင် / ကျောင်းသားဟောင်းအချင်းချင်း / နှစ်ဆင့်အတည်ပြု)
5. **စုဆောင်းရန် မျှော်မှန်းလူဦးရေ** (< 500 / 500-2,000 / 2,000-5,000 / 5,000+ / မခန့်မှန်းရသေး)
