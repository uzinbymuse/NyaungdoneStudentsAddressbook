# Privacy-by-Design၊ OWASP Security၊ ဥပဒေသတိပြုချက်နှင့် Pilot Rollout မှတ်စုများ

## အဓိကအကြံပြုချက် (Findability vs Full Data Exposure)
* “ရှာတွေ့နိုင်ခြင်း (Findability)” နှင့် “ကိုယ်ရေးအချက်အလက်ကို အပြည့်အစုံမြင်ရခြင်း” ကို ခွဲခြားထားရမည်။
* အတည်ပြုပြီးသား ကျောင်းသားဟောင်းများသာ Login ဝင်ကြည့်နိုင်ပြီး ဖုန်း/Email မမြင်ရဘဲ ဆက်သွယ်ရန် တောင်းဆိုနိုင်သော (Relay/Request) စနစ်ကို သုံးရမည်။
* **တက္ကသိုလ်နမူနာများ:**
  * **CCA:** Login ဝင်ထားသော Alumni + သတ်မှတ်ဝန်ထမ်းသာ ကြည့်နိုင်၊ ယခင်အမည် ရှာဖွေနိုင်မှုကို ဖျောက်နိုင်၊ ဖယ်ရှားခွင့် တောင်းဆိုနိုင်။
  * **Indiana University:** Field တစ်ခုချင်းစီ Visibility ထိန်းချုပ်နိုင်၊ Data ပြန်လည်စုဆောင်းခြင်း/စီးပွားရေး/နိုင်ငံရေးစာပို့ခြင်း တားမြစ်။
  * **Penn State:** Directory ထဲမှ Email Relay ဖြင့် ပို့နိုင်သော်လည်း လက်ခံသူ၏ Email အစစ်ကို မဖော်ပြ။

## Data Fields & Minimisation (ICO Privacy-by-Design)
* **အမည်ခွဲခြားခြင်း:** ဘွဲ့/ဘွဲ့အမည် (ဥပမာ- ဓမ္မာစရိယ၊ ပါဠိပါရဂူ)၊ လက်ရှိအသုံးပြုလိုသောအမည်၊ ကျောင်းတက်စဉ်အမည် (ယခင်အမည်ဖြင့် ရှာခွင့်ပြု/မပြု ပိုင်ရှင်ရွေးနိုင်)။
* **ကျောင်းမှတ်တမ်း:** သင်တန်း/အတန်း/စာမေးပွဲအဆင့်၊ တက်ရောက်နှစ်/အောင်မြင်နှစ် (မသေချာပါက “ခန့်မှန်း” မှတ်သားနိုင်)၊ ကျောင်းဆောင်နှင့် နေခဲ့သည့်ကာလ။
* **လက်ရှိနေထိုင်ရာ:** ပြည်တွင်း (တိုင်း/ပြည်နယ် → မြို့နယ် → မြို့/ရွာ/ရပ်ကွက်)၊ ပြည်ပ (နိုင်ငံ → ပြည်နယ်/တိုင်း → မြို့)။ နေအိမ်အမှတ်/လမ်း/အဆောက်အအုံအထိ မတောင်းရ။
* **မတောင်းသင့်သည်များ:** မွေးနေ့အပြည့်အစုံ၊ မှတ်ပုံတင်နံပါတ်၊ အိမ်လိပ်စာအပြည့်အစုံ၊ မိသားစုဝင်အချက်အလက်၊ ID ဓာတ်ပုံများ။
* **အထောက်အထား သိမ်းဆည်းမှု:** စစ်ဆေးအတည်ပြုရန် အထောက်အထားကို ကြည့်ပြီး အတည်ပြုမှတ်တမ်း (Verified Log) သာ သိမ်းရန် — မှတ်ပုံတင်/ဘွဲ့လက်မှတ် Scan ကို Database ထဲ အမြဲတမ်း သိမ်းရန် မလိုအပ်ပါ။
* **Admin မှတ်ချက်:** Directory နှင့် စာအုပ်တွင် မထည့်ရ၊ မှတ်ချက်ထဲတွင် ဖုန်း/သူတစ်ပါးအချက်အလက် မထည့်ရန် သတိပေးရန်။

## Verification, Annual Check & Anti-Scraping
* **Admin Audit Log:** Admin က အခြားသူ Profile ပြင်ပါက ဘယ်အကောင့်က ဘယ်အကွက်ကို ဘယ်နေ့ပြင်သည်ကို Audit Log ထားရန်။
* **နှစ်စဉ် ပြန်လည်စစ်ဆေးခြင်း:** မတုံ့ပြန်သူကို ဖျက်မပစ်ဘဲ “မကြာသေးမီက မအတည်ပြုရသေး” ဟုပြ၍ ရှာဖွေမှုတွင် နောက်တန်းထားနိုင်သည်။
* **OWASP Security Checklist:**
  * Server-side Authorization စစ်ဆေးခြင်း (Deny by default)
  * Login brute-force တားဆီးရန် MFA + Rate Limiting + Generic error messages (မသိသာစေသော error message)
  * HTTPS, Database/Backup Access Control နှင့် Restore Testing
  * Shared Google Sheet link / Public PDF (“link ရှိသူတိုင်းကြည့်နိုင်”) မထားရ
  * တာဝန်ပြီးသွားသော Admin ၏ Access ကို ချက်ချင်း ရုပ်သိမ်းရန်
  * Directory Usage Policy: Data ပြန်ကူး/ဖြန့်ဝေခြင်း၊ စီးပွားရေးကြော်ငြာ၊ နိုင်ငံရေးစာပို့၊ နှောင့်ယှက်ဆက်သွယ်ခြင်း တားမြစ်ချက် ထည့်သွင်းရန်။

## ဥပဒေသတိပြုချက် (Legal Note — Not Legal Advice)
* DLA Piper (2026-02-11) ဖော်ပြချက်အရ မြန်မာနိုင်ငံတွင် အထွေထွေ Data Protection Law တစ်ရပ် မရှိသေးသော်လည်း ၂၀၁၇ ကိုယ်ရေးလုံခြုံမှုနှင့် လုံခြုံရေးဆိုင်ရာဥပဒေ၊ အီလက်ထရွန်နစ်ဆက်သွယ်ဆောင်ရွက်ရေးဥပဒေ ပြင်ဆင်ချက်၊ ၂၀၂၅ Cybersecurity Law တို့ သက်ဆိုင်နိုင်သည်။
* Hosting နိုင်ငံ၊ ပြည်ပ Data ကူးပြောင်းမှုနှင့် ပုံနှိပ်စာအုပ် ဖြန့်ဝေမှုတို့ကို မစတင်မီ ဒေသခံ ဥပဒေပညာရှင်နှင့် စစ်ဆေးသင့်သည်။

## လက်တွေ့စတင်မည့် အစီအစဉ် (Pilot Rollout)
1. Alumni အုပ်စုနှင့် ဆွေးနွေးပြီး Field များ၊ မြင်နိုင်ခွင့်နှင့် Admin စာရင်း သဘောတူညီချက် ယူရန်။
2. ပြည်တွင်း/ပြည်ပနှင့် တက်ရောက်နှစ် မတူညီသူ အနည်းငယ်ဖြင့် **Pilot** စမ်းသပ်ရန်။
3. Self-view/edit/hide နှင့် Anti-bulk-download တို့ကို စမ်းသပ်ပြီးမှ ကျယ်ပြန့်စွာ ဖွင့်လှစ်ရန်။
4. Print Book ကို သီးခြား Opt-in Field များမှသာ ထုတ်လုပ်ရန်။
